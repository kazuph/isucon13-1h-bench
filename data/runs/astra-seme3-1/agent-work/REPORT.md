## 最終構成

| サーバー | 役割 |
|---|---|
| s1 / 10.99.0.11 | nginx による HTTPS 受付、登録済みレコードの DNS 応答 |
| s2 / 10.99.0.12 | Go API、更新用状態と同期済み読み取り状態、永続ジャーナル、初期化用 MySQL |
| s3 / 10.99.0.13 | bcrypt の生成・検証。方式とコストは初期実装を維持 |

- 通常の API 処理から SQL を除去。配信・ユーザー・タグ・コメントなどをメモリ上で索引化。
- コメント、投げ銭、リアクション、視聴者などの集計は更新に追従する。
- 更新はジャーナルへ保存してディスク同期し、読み取り状態への反映を完了してから成功応答する。
- 読み取りは同期済みの状態を使い、無関係な更新のディスク同期を待たない。
- 初期化では提供 SQL から初期状態を構築し、スナップショットとジャーナルを更新する。
- s2 の永続データは `/home/isucon/webapp/state/snapshot.gob` と `journal.jsonl`。
- アイコンの SHA-256 を保持し、対応する条件付き GET に 304 を返す。
- nginx は upstream 接続を再利用し、接続上限を拡大。

## 再起動の確認

全台を実際に再起動。再起動前後で状態全体の SHA-256 と総チップが一致した。

- SHA-256: `0bce5e6f56226e1d8551175dea8434b279343ce4f25e452d82205ddfa64ae8bf`
- サーバー側総チップ: `287078`
- 証跡: `results/fixed-checksum-before.json` / `fixed-checksum-after.json`、`fixed-payment-before.json` / `fixed-payment-after.json`

空のタグ配列が snapshot の復元時に null になる問題を修正し、空配列を保存時と同じ形に復元する。

この環境では再起動で NIC の MAC アドレスが変更される。古い ARP キャッシュによる初回 DNS タイムアウトを防ぐため、`isucon-announce.service` が実インターフェースの競技 IP を通知する。IP 設定用の既存サービスや運営用の保護対象ファイルは変更していない。
