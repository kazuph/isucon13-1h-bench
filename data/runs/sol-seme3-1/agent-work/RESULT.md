初期実装のスコアは **4,593**、現時点の最高スコアは **423,923**（約92.3倍）です。

最終構成は以下のとおりです。

| サーバー | 役割 |
|---|---|
| s1 | Go による TLS/API/静的ファイル配信、メモリ上の全データ・索引・集計、永続ログ、DNS |
| s2 | bcrypt ワーカー、Go のビルド |
| s3 | bcrypt ワーカー |

API の通常処理で SQL は呼びません。初期データは [baseline.json.gz](data/baseline.json.gz)、元の MySQL の比較規則は [collation.bin](data/collation.bin) から読み込みます。bcrypt の方式とコストは初期実装と同じです。

書き込みは `/home/isucon/webapp/state.wal` に順序を保って追記し、ファイルへの書き込み完了を待って応答します。ディスク同期は100msごとです。起動時は初期スナップショットと更新ログから状態を復元します。ユーザー、画像、配信、コメント、リアクション、報告、NGワード、予約枠、視聴者情報を保持します。

DNS は初期ゾーンの名前と登録済みユーザーだけを解決し、応答先は `10.99.0.11` です。この環境のベンチは s2・s3 の IP を DNS 応答に使うと拒否しました。再起動で MAC アドレスが変わるため、各ノードは起動時に自身の競技用 IP を gratuitous ARP で通知します。

[deploy/deploy.sh](deploy/deploy.sh) でテスト・ビルド・配備・自動起動設定を再現できます。既存の更新ログは消去しません。競技サーバー以外への処理の委譲はありません。

検証した内容:

- `go test ./...`：更新ログの再生、途中までの末尾レコード、削除と集計、空画像、スナップショット復元・破損検出、署名不正・期限切れセッション。
- 元の MySQL とメモリ側の LIKE 判定を、英字・アクセント・日本語・ワイルドカードで比較。
- 全3台を再起動し、5,009ユーザー・30,447コメント・23,762リアクション・画像を含む全状態のハッシュが一致。
- 再起動後に、新規登録ユーザーのドメインも名前解決できることを確認。

再起動後のベンチは **415,825点で成功**し、最高点の **98.1%** を再現しました。追試基準の75%を上回っています。結果は [bench-reboot-announced.json](bench-reboot-announced.json)、状態照合は [再起動前](reboot2-before.json)・[再起動後](reboot2-after.json) に記録しました。

最高点のタグは `best-423923`、起動修正を反映した再起動検証済みのタグは `verified-415825` です。APIの処理構成は最高点と同じで、起動時のIP通知と状態照合のメモリ削減を追加しています。
