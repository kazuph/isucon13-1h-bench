何の実装の違いが点差を広げたか(広げた順)

各回の AI の作業ログ(agent.jsonl)と途中のベンチの点(bench.jsonl)を突き合わせて、点が跳ねた直前の変更を拾った。1回のベンチに複数の変更が入っている所は、内訳を分けられていない。各条件は1回ずつなので、ぶれの大きさはまだ測っていない。

  1. MySQL を普段の処理から外し、全データをメモリに持つ書き直し。やったのは攻めの3本だけ。
    • Opus の攻めは、書き直しを入れた最初のベンチで 9,043点から 384,414点になった。Astra の攻めも 8,744点から 260,402点になった。どちらも1回の変更での跳ね。
    • Sol の攻めは段階的に入れた。読み取りの API を全部メモリから返して 154,211点から 217,200点、s1 に読み取り用の複製を置いて 274,943点から 299,291点になった。
    • 書き直さなかった6本は、SQL の手直しと短いキャッシュで頭打ちになった。Astra は13万〜15万点台、Sol は22万点台、Opus の素は33万点台で止まった。
  2. DNS を PowerDNS から自作の DNS に替え、存在しない名前を DB に届けない。ISUCON13 の「DNS の水責め」への対策。
    • Opus の記事の要約は、この置き換えで 218,247点から 289,771点(+71k)になった。Sol の記事の要約は 44,290点から 83,265点(+39k)。Opus の攻めは、存在しない名前に答えず捨てる形にして 373,780点から 400,390点(+27k)。
    • PowerDNS を残したのは Sol の素、Astra の素と記事の要約の3本。この3本は、DB を別の台へ移した直後に点が下がった(例: Astra の記事の要約は 96,246点から 70,251点)。s1 で DNS の処理が CPU を取り合っていた、と AI 自身が記録している。
    • 自作 DNS にしたのは Opus が3本とも、Sol が2本、Astra が攻めの1本だけ。
  3. nginx を外し、Go のアプリが TLS を直接受ける。攻めの Opus と Sol だけ。
    • Opus の攻めは 400,390点から 450,644点(+50k)、Sol の攻めは 300,421点から 323,014点(+23k)。
  4. アイコン画像をアプリに通さずに返す。304 を返す技は9本とも入れたが、そこから先で差が出た。
    • Opus の記事の要約は、画像をディスクに置いて nginx から直接返し、353,343点から 393,969点(+40k)。Sol の記事の要約は、アイコンの短いキャッシュを足した回で 159,950点から 209,349点(+49k。投稿の競合の修正も同じ回に入っている)。
  5. 重い暗号の処理を、空いている s2・s3 に逃がす。やったのは攻めの3本だけ。ほかの6本は s2・s3 を DB 置き場にするか、使わなかった。
    • Opus の攻めは、TLS の署名と bcrypt(パスワードのハッシュ)を s2・s3 に任せて、AI の計測では s1 の CPU の使用が 1.31コアから 0.65コアに減り、453,678点から 463,914点になった。Sol の攻めは bcrypt を移した回で 230,997点から 244,105点(+13k。DB への書き込みを減らす変更も同じ回)。

実装ではないが、点差を広げたこと: GPT の2つは、6本とも60分より前(17〜45分)に「終わった」と報告して自分で止めた。AI には「競技は8時間」と伝えていたので、時間切れを意識した止め方ではない。Opus は3本とも60分を使い切った。Opus の記事の要約は、開始28分で 327,831点だったのを、49分で 402,507点まで上げている。Sol と Astra が止まったのは17〜45分なので、この伸びに当たる時間を使っていない。

全員がやったので、差は広げなかったこと: 索引の追加、N+1 の解消、MySQL の設定(バイナリログを止める、コミットごとの書き込みを緩める)、アイコンの 304。MySQL の設定は1回で大きく効く(Opus の記事の要約で 141,642点から 211,187点)が、ほぼ全員が入れた。
